# 📋 Чек-лист проверки MVP «Оффер где?»

## 🔐 1. Аутентификация и безопасность

### 1.1 Регистрация (`/register`)

- [x] Форма валидирует email (формат `user@example.com`)
- [x] Форма валидирует password (минимум 6 символов)
- [x] При пустых полях показываются понятные ошибки
- [ ] При успешной регистрации — редирект на `/login`
- [ ] При дублировании email — ошибка "Email уже зарегистрирован"
- [ ] Нельзя зарегистрироваться с некорректным email
- [ ] Password не отображается в plaintext (type="password")

### 1.2 Вход (`/login`)

- [ ] Форма валидирует email и password
- [ ] При корректных данных — вход и редирект на `/`
- [ ] При неверных данных — ошибка "Неверный email или пароль"
- [ ] После входа — токен сохраняется, пользователь остаётся залогинен
- [ ] RefreshToken устанавливается в httpOnly cookie
- [ ] AccessToken сохраняется в памяти (не в localStorage)

### 1.3 Выход (`/logout`)

- [ ] Кнопка "Выход" в навигации работает
- [ ] После выхода — редирект на `/login`
- [ ] RefreshToken отзывается на сервере
- [ ] Cookie refreshToken удаляется
- [ ] Повторный запрос к API без токена возвращает 401

### 1.4 Сохранение сессии

- [ ] После перезагрузки страницы пользователь остаётся залогинен
- [ ] При истечении accessToken — автоматическое обновление через `/api/auth/refresh`
- [ ] При отозванном refreshToken — редирект на `/login`
- [ ] При 401 на любом API запросе — попытка refresh → при неудаче выход

### 1.5 Защита маршрутов

- [ ] Незалогиненный пользователь не может открыть `/` (редирект на `/login`)
- [ ] Незалогиненный пользователь не может открыть `/companies`, `/jobs`, `/reminders`
- [ ] После входа redirect на изначально запрошенную страницу (если была)
- [ ] Прямой переход на `/register` или `/login` когда залогинен → редирект на `/`

## ✅ 4. Валидация форм

- [ ] При пустых полях — ошибки отображаются под полями
- [ ] Кнопка "Войти"/"Зарегистрироваться" disabled при невалидных данных

### 4.2 Форма компании

- [ ] Name: обязательно, макс 100 символов
- [ ] Description: опционально, макс 1000 символов

- [ ] Name: обязательно, макс 50 символов

- [ ] Content: обязательно, макс 5000 символов

## 🔒 5. Безопасность (Backend)

### 5.1 Ownership checks

**Тест:** Войти как <alice@example.com>, попытаться получить данные bob'а

- [ ] GET `/api/jobs/:bobJobId` → 404 (не 403, чтобы не раскрывать существование)
- [ ] PUT `/api/jobs/:bobJobId` → 404
- [ ] DELETE `/api/jobs/:bobJobId` → 404
- [ ] GET `/api/companies/:bobCompanyId` → 404
- [ ] GET `/api/notes/:bobNoteId` → 404
- [ ] GET `/api/reminders/:bobReminderId` → 404

### 5.2 Admin read-only

**Тест:** Войти как <admin@example.com>

- [ ] GET `/api/jobs` → возвращает вакансии всех пользователей
- [ ] GET `/api/jobs/:aliceJobId` → успех (может просматривать)
- [ ] PUT `/api/jobs/:aliceJobId` → 403 (не может редактировать чужие)
- [ ] DELETE `/api/jobs/:aliceJobId` → 403 (не может удалять чужие)
- [ ] GET `/api/users` → успех (список всех пользователей)
- [ ] DELETE `/api/users/:userId` → успех (может удалять)

### 5.3 Защита от XSS и инъекций

- [ ] HTML в заметках экранируется (не выполняется)
- [ ] SQL-инъекции невозможны (Prisma использует параметризованные запросы)
- [ ] Content-Type: application/json для всех API ответов

### 5.4 CORS и Cookie

- [ ] CORS настроен только для `http://localhost:5173` (или CORS_ORIGIN из .env)
- [ ] credentials: true для CORS
- [ ] RefreshToken cookie с флагами: httpOnly, sameSite, secure (в prod)
- [ ] RefreshToken НЕ читается из JavaScript (httpOnly)

### 5.5 Rate limiting (опционально, но рекомендовано)

- [ ] Endpoint `/api/auth/login` ограничен (например, 5 попыток в минуту)
- [ ] Endpoint `/api/auth/register` ограничен (например, 3 в час с одного IP)

## 🐛 6. Обработка ошибок

### 6.1 Сетевые ошибки

- [ ] Если backend недоступен — отображается понятная ошибка "Сервер недоступен"
- [ ] Если 500 Internal Server Error — "Ошибка сервера, попробуйте позже"
- [ ] Если 404 Not Found — "Ресурс не найден"
- [ ] Если 403 Forbidden — "Доступ запрещён"

### 6.2 Валидационные ошибки (400)

- [ ] Backend возвращает структурированные ошибки (code + message)
- [ ] Фронтенд отображает понятные сообщения из backend
- [ ] Ошибки привязаны к конкретным полям формы (если возможно)

### 6.3 Пустые состояния

- [ ] Если нет компаний — "У вас пока нет компаний. Добавьте первую!"
- [ ] Если нет вакансий — "У вас пока нет вакансий. Добавьте первую!"
- [ ] Если нет напоминаний — "У вас нет напоминаний."
- [ ] Канбан пустой — призыв добавить вакансию
